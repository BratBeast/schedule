# Звіт-Ретроспектива за Лабораторною Роботою №3: Використання зовнішніх бібліотек/фреймворків

Цей звіт підсумовує досвід використання зовнішніх бібліотек/фреймворків Python для реалізації функціоналу Telegram-бота-планувальника.

---

## 📚 Використані бібліотеки

| Бібліотека | Призначення |
| :--- | :--- |
| **aiogram** | Асинхронний фреймворк для Telegram-бота (UI, FSM, хендлери). |
| **pandas** | Робота з табличними даними, фільтрація та сортування розкладу з CSV. |
| **apscheduler** | Планувальник завдань для фонової перевірки нагадувань. |
| **pytest** | Фреймворк для юніт-тестування критичної бізнес-логіки. |

---

## 🧐 Детальний аналіз використання бібліотек

### 1. Які конкретні задачі планували вирішувати за допомогою цієї бібліотеки?

| Бібліотека | Вирішувані Задачі |
| :--- | :--- |
| **aiogram** | Реалізація інтерактивного інтерфейсу, керування станами користувачів (вибір групи, налаштування нагадувань), обробка команд та кнопок. |
| **pandas** | Швидке та надійне завантаження, парсинг (включно з різними кодуваннями), фільтрація та, що критично, числове сортування розкладу за часом. |
| **apscheduler** | Забезпечення постійної фонової роботи функції `check_upcoming` з інтервалом в 1 хвилину, щоб надсилати нагадування користувачам. |
| **pytest** | Перевірка коректності логіки сортування за часом (`time_to_minutes`), логіки фільтрації та, найголовніше, коректності спрацьовування нагадувань. |

### 2. Чому було обрано саме цю бібліотеку, а не аналоги?

* **aiogram:** Обрано через його асинхронну природу (`async/await`), що є стандартом для сучасних, швидких ботів у Python. Це дозволяє боту легко обробляти планувальник (`apscheduler`) та одночасно реагувати на повідомлення.
* **pandas:** Це галузевий стандарт для роботи з табличними даними. Його індексація та можливості фільтрації (`DataFrame`) значно спростили маніпуляції з розкладом, роблячи код значно чистішим, ніж ручний парсинг CSV.
* **apscheduler:** Це планувальник, який має вбудовану та надійну підтримку `AsyncIOScheduler`, що дозволяє йому безконфліктно працювати у тому ж циклі подій, що й `aiogram`.
* **pytest:** Обрано як найсучасніший, мінімалістичний та потужний фреймворк для тестування у Python, який є гнучким для написання складних моків (mocking).

### 3. Наскільки просто та зрозуміло було отримати, встановити, налаштувати та почати використовувати цю бібліотеку?

Усі бібліотеки встановлюються легко через `pip`. Налаштування було простим: `pandas` і `pytest` не вимагали спеціального налаштування. `aiogram` та `apscheduler` вимагали лише базової ініціалізації об'єктів.

### 4. Наскільки зрозумілою та корисною була документація бібліотеки?

Документація була дуже корисною. Для `aiogram` (приклади FSM) та `pandas` (приклади фільтрації) вона була вичерпною. Для розв'язання специфічної проблеми з мокінгом системного часу в `pytest` знадобилися додаткові ресурси, оскільки це не є стандартною поведінкою.

### 5. Наскільки було зрозуміло, як саме використовувати бібліотеку?

Загалом, зрозуміло. Основні класи та методи були інтуїтивними. Проте, не була очевидною необхідність нормалізації часу (видалення провідного нуля `08:40` -> `8:40`), що було виявлено лише на етапі тестування.

### 6. Наскільки зручно було використовувати бібліотеку, чи не треба було писати багато надлишкового коду?

* **pandas:** Дуже зручно, економить сотні рядків коду порівняно з ручною обробкою даних.
* **aiogram:** Зручно, хоча для мінімального функціоналу (FSM, ініціалізація) вимагає певного "boilerplate-коду".
* **apscheduler:** Максимально зручно, оскільки одна функція замінила необхідність писати власні цикли та логіку таймінгу.

### 7. Наскільки зрозумілою була поведінка класів/методів/функцій з бібліотеки?

Поведінка була зрозумілою, за винятком модуля `datetime` (стандартна бібліотека), який при мокінгу поводився неочікувано (помилка `TypeError` через його "незмінність"), що вимагало обхідного рішення.

### 8. Наскільки зрозумілою була взаємодія між різними класами/методами цієї бібліотеки, а також взаємодія між бібліотекою та власним кодом?

Взаємодія була чистою та логічною:
* `aiogram` (диспетчер) асинхронно викликає власні хендлери.
* `apscheduler` (планувальник) асинхронно викликає функцію `job()`, яка використовує асинхронний `aiogram` для відправки повідомлень.

### 9. Чи виникали якісь проблеми з використанням бібліотеки? Чи вдалось їх вирішити, як саме?

| Проблема | Бібліотека | Вирішення |
| :--- | :--- | :--- |
| `TypeError` при мокінгу `datetime.now()` | `pytest`/`datetime` | Вирішено шляхом заміни всього класу `datetime` у просторі імен модуля `bot` на власний клас-заглушку (`MockDatetime`). |
| `AssertionError` (Неспрацьовування нагадувань) | `pandas`/Власний код | Вирішено шляхом нормалізації формату часу: додано логіку для видалення провідного нуля (`08:40` -> `8:40`) у функції `check_upcoming`. |

### 10. Що хорошого можна сказати про цю бібліотеку, які були позитивні аспекти використання бібліотеки?

* **aiogram:** Швидкість, стабільність, легкість інтеграції асинхронних завдань.
* **pandas:** Потужність, можливість обробляти `schedule.csv` (включно з різними кодуваннями) одним-двома рядками коду.
* **pytest:** Чистота та мінімалізм тестів, зручні фікстури.

### 11. Що поганого можна сказати про цю бібліотеку, які були негативні аспекти використання бібліотеки?

* **pandas:** Додає велику залежність для відносно простого завдання (збільшує розмір проєкту).
* **Модуль datetime:** Складність тестування методів, що використовують системний час, через його "незмінність" (вимагає складного мокінгу).
* **Залежність від формату даних:** Виявлено, що логіка сильно залежить від формату `H:MM` у CSV.

### 12. Якби довелось вирішувати аналогічну задачу... що варто було б робити так само, а що змінити?

* **Залишити aiogram та apscheduler:** Ця комбінація асинхронного UI та планувальника є ідеальною для ботів.
* **Змінити мокінг часу:** Використати спеціалізовану бібліотеку `freezegun`, щоб уникнути складного мокінгу `datetime` у `pytest`.
* **Додати логіку тижнів:** Реалізувати фільтрацію за парним/непарним тижнем, щоб повністю відповідати вимогам реального розкладу (оскільки це єдина невиконана бізнес-вимога).
